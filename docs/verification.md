# Проверка 18 сентября 2026

Проверка проводилась через Playwright CLI в настоящих браузерных движках Chromium
(Chrome) и WebKit 26.6. Это автоматизация браузера на Mac с размерами планшета;
физический iPad/Android-планшет к сессии не подключён.

## Проверенные сценарии

- Первый запуск: 1 800 ₽, три исходных набора, корректные дата и возраст.
- Покупка: точное списание цены, сохранение набора, записи истории и цели.
- Все три задания, недельное ограничение, однократная продажа велосипеда.
- Неделя и календарный месяц, остаток дней, повторное открытие незавершённого начисления.
- Отсутствие повторного начисления и повторного случайного выбора при перезагрузке.
- Баланс, полка, история, вкладка, страница каталога и настройки после перезагрузки.
- Отмена сброса, подтверждение сброса и сохранение новой игры после перезагрузки.
- Необязательные HTML-экспорт/импорт и сброс в экспортированной игре.
- Повреждённый импорт не заменяет текущую игру; повреждённая основная запись
  восстанавливается из предыдущей автокопии с уведомлением.
- Обработка недоступного хранилища: заметное сообщение, доступная резервная копия.
- Миграция состояния со схемами v2 и v3, обновление игры в другой открытой вкладке.
- 31 января → 28 февраля; чередование месяца и недели; день рождения, 29 февраля
  в обычном году, Новый год; применение будущей стартовой даты без потери текущей игры.
- Запуск и сохранение без сети в Chromium; в WebKit — при остановленном локальном
  HTTP-сервере, с двумя перезагрузками и начислением денег между ними.
- Размеры 1024×768, 768×1024, 1024×600 и 390×844: нет горизонтального переполнения,
  кнопки умещаются в карточки; сделаны снимки экрана.

В Chromium основной прогон содержит 38 проверок, дополнительный — 13.
В WebKit подтверждены 27 основных проверок, запуск и сохранение при недоступном
сервере и все четыре размера экрана. Переключение `context.setOffline(true)`
в Playwright WebKit вызывает внутреннюю ошибку навигации; вместо этого для
офлайн-проверки фактически остановлен HTTP-сервер. Игра продолжила запускаться
из кэша, начислять деньги и восстанавливать прогресс.

## Первоначальная публикация

`https://0range.github.io/tim-kopilka/` возвращает HTTP 200. GitHub Pages успешно
публикует корень `main`. SHA-256 опубликованного `index.html` совпадает с локальным:
`c399491946f7d2b1ffcc37d2150d05a4102381a46211a7812c9af0ca905de15a`.

В Chrome и WebKit на опубликованном адресе подтверждены:

- запуск со всеми изображениями;
- ход, сохранение и перезагрузка;
- подтверждённый сброс, затем перезагрузка с начальным состоянием;
- manifest и PNG-иконки доступны, scope/start URL указывают на `/tim-kopilka/`;
- режим `standalone`, работающий service worker и кэш приложения;
- отсутствие ошибок JavaScript.

## Исправленные ошибки исходного файла

1. В скачанной игре сброс мог отменяться при перезагрузке: встроенный старый ID
   получал приоритет. Для копии используется постоянный отдельный ключ хранения.
2. Вкладка и страница каталога не сохранялись. Теперь они входят в состояние.
3. Проверка импорта не проверяла вложенные объекты; `owned: [null]` проходил её
   и ломал игру. Вложенные настройки, покупки, история и события валидируются.
4. Повреждённая основная запись могла уничтожить доступное сохранение. Кандидаты
   читаются отдельно, хранится предыдущая корректная автокопия.

Артефакты браузерных проверок находятся локально в `output/playwright/` и не
публикуются: они содержат тестовые игры. Исходный HTML до исправлений сохранён в Git.
